# Session Log

Rolling log of work sessions. Append new entries at the **bottom** (oldest first, newest last) and read the **last 3 entries** to catch up. This file holds only the newest ~12 entries so it can be read whole. When it passes 15 entries, move the oldest, unedited, into the monthly archive until 12 remain (see the context maintenance protocol in `AGENTS.md` and [ADR 0063](./decisions/0063-session-log-archive-by-month.md)). Never rewrite history, and never summarise an entry on the way.

> **Older entries are not lost.** Every entry older than the ones below is in [`docs/archive/session-log/`](./archive/session-log/README.md), one file per month, as it was written. Search it with grep instead of reading it (the README there has the commands). The Phase 0–10 build history is in the compressed [`session-log-archive.md`](./archive/session-log-archive.md) (Rollup 1 = Phases 0–7, Rollup 2 = Phase 8 + Phase 9, Rollup 3 = Phase 9 follow-ups + Phase 10). Per-feature build detail: [`/docs/archive/`](./archive/).

## 2026-11-21 — Rolling out category-wise subscription: migration, deploy, and a link bug (#285, #294)

- **Rollout:** the local `.env` points at a Postgres on this Mac, not Neon, so the first `alembic upgrade head` hit the local database; deploying revision `00008-rjn` then returned 500 on `/ipos` (`column ipos.sub_qib does not exist`) and traffic was put back on `00007-5sv` within minutes. The production migration was then run with the connection string read from Secret Manager (`fundamentals-database-url`, never printed), traffic moved to `00008-rjn`, and `/ipos` returns 200 with the new fields. Lesson: `alembic current` matching a revision does not prove the target; check the host first.
- **Bug found by the first `refresh-ipos` run:** it read category data for 0 IPOs. Live row links are relative; the saved fixture had absolute ones. Fixed in #294 (no redeploy needed: the job imports the parser from the repo).
- **Second find (#296):** with the links fixed, the CI render timed out on every subscription page: the table is not in the DOM until client hydration, which headless CI never reached. A plain GET returns 200 (no challenge) with the table inside the Next.js server payload (both days, current). The job now fetches those pages with `httpx` and `parse_subscription` reads the DOM table or, failing that, the decoded payload. Checked against the live pages: Watrana matches the maintainer's saved page exactly.
- **Result:** after #297 a manual `refresh-ipos` run read 3 IPOs and production `/ipos` has the category figures (job about 30 s). HANDOFF and POST-PAUSE-CHECKS updated. Remaining: the UI and brief are unverified until the app deploy; odds accuracy against a real basis of allotment.
