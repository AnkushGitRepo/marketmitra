# Session Log

Rolling log of work sessions. Append new entries at the **bottom** (oldest first, newest last) and read the **last 3 entries** to catch up. This file holds only the newest ~12 entries so it can be read whole. When it passes 15 entries, move the oldest, unedited, into the monthly archive until 12 remain (see the context maintenance protocol in `AGENTS.md` and [ADR 0063](./decisions/0063-session-log-archive-by-month.md)). Never rewrite history, and never summarise an entry on the way.

> **Older entries are not lost.** Every entry older than the ones below is in [`docs/archive/session-log/`](./archive/session-log/README.md), one file per month, as it was written. Search it with grep instead of reading it (the README there has the commands). The Phase 0–10 build history is in the compressed [`session-log-archive.md`](./archive/session-log-archive.md) (Rollup 1 = Phases 0–7, Rollup 2 = Phase 8 + Phase 9, Rollup 3 = Phase 9 follow-ups + Phase 10). Per-feature build detail: [`/docs/archive/`](./archive/).

## 2026-11-15 — Stalled local analyst runs capped at two (#200)

- Found by reading the System logs after the #196 fix had run for 10h42m on a laptop that slept. At 21:38 IST, after a 5h52m silence, five sweeps and four dispatches were logged within 12 seconds. They were not fresh runs: their `durationMs` was 28 to 272 minutes, so they had started between about 17:06 and 21:10 (roughly hourly, which looks like brief wake-ups during sleep), stalled when the machine went back to sleep, and finished together on wake. The #196 cap let a new run start whenever the previous one was older than 15 minutes, with no limit on how many piled up.
- Fix: at most two runs in flight (`MAX_RUNS_IN_FLIGHT`), none started beside a run younger than 15 minutes, and a run still pending after 12 hours (`RUN_ABANDON_MS`, longer than a night's sleep) no longer holds a slot, so a run that never returns still cannot stop the schedule for good. The state changed from one `busySince` to a list of run starts. Known consequence, written into ADR 0062: while two stalled runs hold both slots nothing starts, the dispatch check included, until one finishes; on a sleeping laptop that is the wake.
- **Verified:** pure tests for the slot rules, and a fake-timer test that reproduces the night (three hours of due ticks with every sweep stalling started 9 extra sweeps before the cap and 2 after; once the stalled runs finish the cadence resumes); lint, typecheck, the full suite (1749 tests) and `next build` in a copy of the tree with CI's placeholder env. **Not verified:** a real night of sleep on the fixed code. Whether the stalled runs of 2026-11-15 spent AI calls twice is not known; the log shows 0 initiated and 3 journaled across all six runs, and nothing visibly duplicated.
