## If you remember only eight things

1. `AGENTS.md` is the rulebook. Issue → branch `fix|feat|chore|docs/<issue#>-slug` → PR (template, `Closes #N`) → squash merge when checks are green → update `main`.
2. Never deploy to production, run production migrations, or touch secrets without the maintainer's go-ahead. **A deploy does not mean a new version** ([ADR 0059](./decisions/0059-deploys-do-not-imply-a-version.md)): deploy `main` as is; cut a release only when asked.
3. Next.js is **v16 with breaking changes** — read `node_modules/next/dist/docs/` first. The middleware file is `src/proxy.ts`. App pages are top-level (`/portfolio`, not `/dashboard/portfolio`; only `/dashboard` is the home) — see [ADR 0037](./decisions/0037-top-level-app-routes.md); a new page must be registered in `src/lib/routes.ts` and `src/proxy.ts` (a test enforces it).
4. CSS Modules + tokens only. No Tailwind. Every feature = UI **and** a documented API route (`public/openapi.json`).
5. No paid tier, ever. Hosted vs self-host is gated by `isHosted()`.
6. The **Mitra Advisor** is off by default and recommend-only (ADR 0035). Local install, or a hosted admin in `ADMIN_USER_IDS` with `ADVISOR_MODE=enabled` set on the host (ADR 0070; the Vercel variables are still to be set, see Open work).
7. Verify before claiming: check production state yourself, report what was and wasn't tested.
8. Keep this file and `docs/session-log.md` current.

**Mitra memory, 2026-11-26 (issue #402, ADR 0083; PR open, not yet merged; the last of the three agreed Mitra pieces):** Mitra saves durable facts the user states and uses them in every chat. `remember` takes a fact plus a verbatim quote and the code refuses it unless the quote is in the user's own typed messages (`memory/rules.ts` `quoteIsFromUser`), so a file, page, note or tool result cannot create one; private data (PAN, Aadhaar-like, card, phone, email, password, OTP...) is refused in code; a repeat updates the existing memory; max 100 per user, 300 characters each. Withheld while a file is attached and in advisor-only mode; `forget` deletes by id. A chip in the reply shows what was saved with Undo; Settings > AI & Models has the switch (`chat.memory`, default on) and `MemoryPanel` (list, Add, Delete, Forget everything); `/api/mitra/memories` (+ `{id}`) is documented; memories are in the data export. The 40 newest go into the Mitra page and drawer prompts as background. **Verified:** unit tests, lint, typecheck, and live: three facts from one message each got a chip, a new chat answered "given your conservative risk tolerance and 12-year horizon… excluding tobacco and alcohol" without being told again, a PAN and phone number were refused with no chip, the Settings list and its Delete button worked, and all test memories and chats were deleted. **Not verified:** a file or web page trying to plant a memory (unit-level only), other providers, the drawer, two hosted accounts, production. **Open:** there is no account-deletion flow yet; it must delete `mitraMemories` when it exists.

**Mitra web search, 2026-11-26 (issue #401, ADR 0082; PR open, not yet merged; #402 memory is next):** the Mitra page and the chat drawer have `web_search` and `fetch_page` (`lib/mitra-chat/webTools.ts` wrapping `lib/ai/research/webTools.ts`) for every provider: 3 searches and 2 pages per reply, results fenced as untrusted, `fetch_page` only for an address from a search in this reply or one the user typed (so a page or note cannot carry data out in an address), withheld while a file is attached and in advisor-only mode, and a Settings switch (`chat.webSearch`, default on). `WEB_SEARCH_PROMPT` requires inline source and date and a Sources line (the first live run gave none until the prompt was tightened). **Verified:** unit tests, lint, typecheck, and live: a Vodafone Idea AGR question used the knowledge base, one web search and two page reads and answered with specifics, and a TRAI/DoT question answered with an inline source and date and a Sources line; the switch round-trips through the preferences API and its row shows under AI & Models; test chats deleted. **Not verified:** the attached-file gating live (unit-level only), providers other than Gemini, the drawer, production. **Known limit:** the keyless sources are best-effort and the query privacy rule is enforced by the prompt, not code.

**Mitra and your notes, 2026-11-26 (issue #400; PR open, not yet merged; #401 web search and #402 memory are next, in that order, agreed with the maintainer):** Mitra could only similarity-search notes (six passages, often all from one long report), so "list my notes" named one of three. **Notes reader layout, 2026-11-26 (issue #396; PR open, not yet merged):** `/notes` is a 300px list plus a reader that takes the rest, with a "Hide list" toggle (desktop only; on a phone the list and the note are still separate views), a compact sticky list (one-line titles, delete on hover or focus with the existing confirmation), and a toolbar at the top of the note (Edit, Ask Mitra, Export as PDF / Word / Markdown / text, Delete) that stays in view on desktop. **Head-to-head compare, 2026-11-26 (issue #394; PR open, not yet merged): the Research Compare tab is now a streamed seven-chapter report** (`POST /api/research/compare-report` with `{ symbols: [2 to 4] }`, `lib/research/compare/`, chapter ids `cmp_*`). `analysis.ts` holds the arithmetic: category leaders (a negative net worth is never "safe"), and `trajectory()`, one shared fiscal-year axis (March year ends) with three projected years that are each company's own growth carried forward and fading by a fifth a year, capped at +30% / -15%, drawn dashed and labelled as a projection, **not analyst consensus**; the growth index starts every company from the first year they all have. New block type `trajectory_chart` (tabs for revenue, operating profit and growth; `lib/research/trajectory.ts` geometry shared by `TrajectoryChart.tsx` and the PDF; Word and text get it as a table via `chartTables.ts`), and `DataTableBlock.highlights` marks the best cell of a row for the transposed matrix. Search calls: business and sector measures, issues, outlook; then the verdict is written from their text (so it cannot contradict them), then the questions, then one JSON extraction for the sector-measures table, profile cards and issue cards (companies the model names that are not in the comparison are dropped). The Compare tab has four one-click presets, tables wrap their headers so the last column is no longer pushed off the card, and the page has 96px under the last block for the chat button. **Verified:** unit tests, lint, typecheck, one live run (JPL vs BHARTIARTL vs IDEA, 7 of 7 chapters), its PDF rendered through Chrome and Ghostscript, and the page replayed in the browser (tabs, hover, no table overflow at 1280px, no page overflow at 390px, 0 console errors). **Not verified:** Word and text export of a real run, banks and IT comparisons (the sector measures are chosen by the model from the guidance), non-Gemini providers, production. **Known limits:** P/E is not ranked in the matrix (a low multiple is not better in itself); a company with fewer than three fiscal years or a loss history is not projected; the old non-streamed `/api/research` comparison path still exists but the page no longer uses it.

**Portfolio report, 2026-11-26 (issue #390; PR open, not yet merged): the Research Portfolio tab is now a streamed seven-chapter forensic review** (`POST /api/research/portfolio-report`, `lib/research/portfolio/`, chapter ids `pf_*`). `analysis.ts` holds all the arithmetic (attribution and gain concentration, CRITICAL/MODERATE/NORMAL severity at -30%/-15%, value-weighted ROCE/ROE/debt and a harmonic P/E, a rule-based risk register and a health score that is 100 minus fixed points per register item, name-based economic-driver buckets, and a one-standard-deviation range from each holding's own one-year volatility; base case = today, no expected return). `gather` reads the holdings, each one's screener row (`q` match, exact symbol) and `getPrices(…, '1y')`, covering the 25 largest by cost. Four chapters call the model (losers and the exposure chapters search the web, aimed at holdings 15% or more below cost and positions over 12%), the checklist is written last and turned into numbered cards. Reuses the sector report's stream, jump bar and four exporters (`ExportMeta.kind` = `portfolio`); card tags CRITICAL/MODERATE are coloured. **Follow-up #392:** the health chapter is written after the losers/exposure/risk chapters from their text (so it cannot say nothing was found), chapter 2 also holds a winners valuation table and a three-bullet check, and the PDF watermark is two non-wrapping lines behind the content. **Verified:** unit tests, lint, typecheck, one live run on the real portfolio (13 holdings, 7 of 7 chapters, 0 console errors) and the PDF of two live runs rendered through Chrome and Ghostscript. **Not verified:** the PDF/Word/text export of a real portfolio run, phone layout, non-Gemini providers, production. **Known limits:** the driver buckets read sector and industry names, so an odd label lands in "Other"; debt/equity of 0.0 for some companies is what the data service holds; the volatility range assumes holdings move together (stated on the page); a book over 25 holdings is cut to the biggest by cost; the old non-streamed `/api/research` portfolio path still exists but the page no longer uses it.

## Gotchas that already cost us time

0. **A failed MongoDB connect used to stick** (#158): `src/lib/mongodb.ts` connected once at import, so one cold-start failure (`MongoServerSelectionError ... ReplicaSetNoPrimary`) broke every request on that instance. It now connects lazily, never caches a failure and retries once. If you see that error in production logs again, it is Atlas reachability (check the cluster and its network access list), not the code.

0b. **Long AI generations need room, and Safari reports a non-JSON reply oddly** (#162): a brief on the thinking model takes about 35 to 100 s, so one-shot AI routes need `maxDuration = 300` (the plan maximum; 60 s cuts them off with a plain-text timeout page). Safari's `response.json()` on that page throws "The string did not match the expected pattern." A client that calls an AI route should read the reply defensively and map it with `src/lib/http/generationError.ts`. **Open risk:** Safari may drop a request that is silent for about 60 s even when the server allows 300 s; if a brief still fails there, keep the response alive with periodic whitespace or generate asynchronously and poll. A finished brief is cached for 24 h, so retrying shows it at once.

1. **Next 16:** the request middleware is `src/proxy.ts` (not `middleware.ts`). Read the bundled docs; don't rely on older Next knowledge.
2. **macOS is case-insensitive:** `Pagination.tsx` and `pagination.ts` in the same folder clash. Name helpers differently (`pageMath.ts`).
3. **Stray duplicate files** named like `name 2.ext` (an IDE/file-sync bug) appear locally, are byte-identical and gitignored (`* [2-9].*`), but break `tsc`, `next build` and Alembic ("Multiple head revisions") when inside scanned folders. 5. **Embeddings run in `fundamentals-api` `POST /embed`** (`fastembed`, 384-dim), never in the Next app — `onnxruntime-node` can't load on Vercel. `EMBED_DIM = 384` must stay in lockstep across `src/lib/rag/embed.ts`, `app/ingestion/embeddings.py` and the Atlas Vector Search index def in `src/lib/rag/chunks.ts`.

15. **Stray `* 2.*` duplicates are recreated in `src/` as you edit, and `vercel deploy` uploads them.** They are gitignored (so CI is green) but break the remote `tsc` (e.g. `index 2.ts` importing a deleted file) and the deploy fails.
