## 2026-11-11 — A failed MongoDB connect on a cold start no longer breaks every request (#158)

- Hosted `/agents` showed "The analyst roster could not be loaded right now". **Diagnosis from the production runtime logs:** `MongoServerSelectionError: Server selection timed out after 5000 ms` (`ReplicaSetNoPrimary`), logged as an `unhandledRejection`; not a schema or undefined-field crash (the roster loads locally against the same database). **Root cause:** `src/lib/mongodb.ts` evaluated `client.connect()` once at module load, so a failed first connect on a cold start stayed a rejected promise for the life of the instance and every Mongo-backed request on it failed until it recycled. It affected the whole hosted app, not just this page.
- **Fix:** the client connects lazily on first use and a failed connect is never cached; `getDb()` retries once before giving up, and there is no import-time rejection. The Analyst Desk now shows "Unable to load your analysts" with a **Reload roster** button (the one-off analysis below stays usable) and logs the cause by error name (`page:agents`).
- **Verified:** lint, typecheck, unit tests (no connect at import, connection reuse, one retry, a rejected promise is never cached); in a browser the error card (forced failure, reverted) and the real roster after reverting (deck and 13 cards). **Not verified on production** (needs a deploy). The pasted theory (undefined fields on legacy records, a `/api/agents` 500) did not match the logs; legacy records already get defaults in `toRecord`.

## 2026-11-11 — Brief generation no longer ends in a Safari parser error (#162)

- Maintainer report (Safari, hosted): generating the 360 brief showed "The string did not match the expected pattern."
